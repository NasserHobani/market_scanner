# النشر بـ Docker

## ⚠ اقرأ هذا أوّلاً — لا تسجيل دخول في هذا النظام

لا صفحة واحدة في اللوحة تسأل عن هويّة. ولا `login_required` في
الكود كلّه. وهذا كان قراراً واعياً حين كانت الواجهة على شبكتك
المحلّية وحدها.

**والخادم شيءٌ آخر.** من يعرف العنوان يستطيع:

- قراءة صفقاتك ومحفظتك وكل ما مسحه النظام
- تغيير الإعدادات وحدود المخاطرة
- تشغيل المسح والتدريب — أي استهلاك مفاتيحك عند Alpaca و Claude
- حظر الرموز وتعديل المهامّ المجدولة

ولهذا يربط `docker-compose.yml` المنفذ بـ `127.0.0.1` — أي أنّه
**غير مفتوح للإنترنت** حتى بعد التشغيل. وثلاثة مخارج:

**١) نفق SSH — الأبسط والأكفأ اليوم**

```bash
ssh -L 8000:127.0.0.1:8000 user@server
```

ثمّ افتح `http://127.0.0.1:8000` على جهازك. لا شيء مكشوف، ولا
شهادة تُدار، ولا كلمة مرور إضافية تُنسى.

**٢) وكيل عكسيّ بكلمة مرور** — Caddy أو nginx أمام الحاوية، مع
`basicauth` و TLS. يفيد إن أردت الفتح من الجوّال بلا نفق.

**٣) استيثاق داخل التطبيق** — الحلّ الصحيح على المدى الطويل، وهو
غير مبنيّ بعد. `django.contrib.auth` مركَّب أصلاً، فالعمل هو
وسيطٌ يشترط الدخول على كل مسار عدا `/healthz/`.

ولا تحذف `127.0.0.1` من `ports` قبل أن تنفّذ واحداً من الثلاثة.

## ما الذي يعمل ولماذا

ثلاث حاويات:

| الخدمة      | ماذا تفعل                          |
|-------------|------------------------------------|
| `db`        | PostgreSQL 16 — لا منفذ على المضيف |
| `web`       | gunicorn بثلاثة عمّال، بلا جدولة   |
| `scheduler` | نسخة واحدة تنادي `run_jobs` دورياً |

**ولماذا فُصل المجدول.** `cron.start()` يعمل في
`AppConfig.ready()` — أي في **كل عامل gunicorn**. فثلاثة عمّال
بلا فصل يعني ثلاثة محرّكات على قاعدةٍ واحدة: كل مسحٍ ثلاث مرّات،
وكل صفقةٍ ورقية ثلاثاً. لذلك `SCHEDULER_ENGINE=off` في `web`،
والجدولة حاوية مستقلّة **واحدة**.

لا تُشغّل `--scale scheduler=2`. لن يمنعك Docker، وستُشغَّل كل
مهمّة مرّتين.

## التشغيل

```bash
git clone <رابط-المستودع> market-scanner
cd market-scanner

cp .env.docker.example .env
nano .env            # املأ المفتاح السرّي وكلمة مرور القاعدة

docker compose up -d --build
docker compose logs -f web
```

ثمّ من جهازك: `ssh -L 8000:127.0.0.1:8000 user@server` وافتح
`http://127.0.0.1:8000`.

**التحقّق من الصحّة:**

```bash
docker compose ps                     # الحالة يجب أن تكون healthy
curl -s localhost:8000/healthz/       # ok
docker compose logs scheduler | tail  # دورات الجدولة
```

## نقل بياناتك الحالية إلى الخادم

الخادم يبدأ بقاعدةٍ فارغة. ولنقل الـ ١٣٬٢٩٠ صفّاً التي عندك:

**١) على جهازك — رحّل إلى PostgreSQL محلّياً أوّلاً**، باتّباع
`docs/POSTGRES.md`. لا تتخطّ هذه الخطوة: `pg_dump` من قاعدةٍ
موجودة أضمن كثيراً من محاولة نقل SQLite إلى خادمٍ بعيد مباشرةً.

**٢) صدّر:**

```bash
pg_dump -U postgres -d scanner -Fc -f scanner.dump
```

**٣) انقل واستورد:**

```bash
scp scanner.dump user@server:~/
docker compose cp ~/scanner.dump db:/tmp/scanner.dump
docker compose exec db pg_restore -U scanner -d scanner \
    --no-owner --clean --if-exists /tmp/scanner.dump
```

**٤) الشموع ولقطات الميزات** ليست في القاعدة — ٤٤٨ ميغابايت من
الملفّات في `data/`. وهي تُبنى من جديد مع أوّل مزامنة، فلا يلزم
نقلها. وإن أردت توفير وقت المزامنة الأولى:

```bash
rsync -avz data/ user@server:~/market-scanner-data/
docker compose cp ~/market-scanner-data/. web:/app/data/
```

**ولا تحذف قاعدتك القديمة** بعد النقل. هي سجلّ ٦٢٤ صفقة وعمل
أشهر — واحتفظ بها حتى تتأكّد أنّ الخادم يعمل أسبوعاً كاملاً.

## التحديث بعد تعديل الكود

```bash
git pull
docker compose up -d --build
```

الهجرات تُطبَّق تلقائياً عند إقلاع `web`. والمجدول ينتظر انتهاءها
قبل أن يبدأ — فحاويتان تهاجران معاً تتسابقان على جدول
`django_migrations`.

**التراجع عن نشرةٍ سيّئة:**

```bash
git checkout <الوسم-السابق>
docker compose up -d --build
```

وهذا وحده سببٌ كافٍ لوسم كل نشرة: `git tag -a v1 -m "أوّل نشر"`.

## الأعطال المتوقّعة

**«Bad Request (400)»** — اسم النطاق غير مذكور في
`DJANGO_ALLOWED_HOSTS`. أضفه في `.env` وأعد `docker compose up -d`.

**اللوحة بلا نمطٍ ولا رسوم** — فشل `collectstatic`. اقرأ
`docker compose logs web | head -40`.

**«LightGBM UNAVAILABLE»** — لا ينبغي أن تظهر هنا: الصورة تثبّت
`libgomp1` و `lightgbm`. وإن ظهرت فالسبب في السجلّ لا في التخمين.

**كل مهمّة تعمل مرّتين** — مجدولان. تحقّق:
`docker compose ps scheduler` يجب أن يُظهر نسخةً واحدة، و
`SCHEDULER_ENGINE=off` في حاوية `web`.

**الأوقات بفارق ثلاث ساعات** — `TZ` أو `SCANNER_TIMEZONE` لم
يصل. الصورة تثبّت `tzdata` وتضبط `Asia/Riyadh`.

**القرص يمتلئ** — السجلّات محدودة بـ 20م × 5 لكل خدمة. والمتبقّي
غالباً `data/` (الشموع) أو نسخ القاعدة. `docker system prune -a`
يحذف الصور القديمة لا البيانات.

## ماذا يبقى خارج الصورة

`.dockerignore` يمنع `data/` (٤٤٨م) و `reports/` و `.env`
و `*.sqlite3` و `.git/`.

و**منعُ `.env` ليس تزيّداً**: مفاتيح Alpaca تفتح الحساب وتسمح
بإرسال الأوامر. وملفٌّ يدخل الصورة يُقرأ بـ `docker history` من
كل من يسحبها — ولو لم يُرفع إلى GitHub قطّ.
