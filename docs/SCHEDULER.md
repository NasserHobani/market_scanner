# الجدولة

## أين تعمل المهامّ

المهامّ الأربع — المسح · مزامنة الشموع · مراقبة الفرص · حسم
الصفقات — تعمل **داخل الخادم** افتراضياً. فإغلاق نافذة الخادم
يوقفها جميعاً، ولا شيء ينبّهك: الشاشة التي تنبّه لا تُفتح حينها.

## التحكّم من الواجهة

`/jobs/` تعرض كل مهمّة وحالتها وآخر تشغيل والموعد القادم وسجلّ
آخر مئتي تشغيل. ومنها تُغيّر الفترة وتوقف وتشغّل وتضغط «شغّل الآن».

الجدولة **بيانات** في القاعدة (`ScheduledJob`)، لا ثوابت في
الشيفرة. وتغييرُ فترةٍ لا يحتاج إعادة تشغيل.

## التشغيل والخادم مغلق

اربط هذا الأمر بمجدول النظام:

```
python web/manage.py run_jobs
```

يسأل القاعدة عن المستحقّ، يشغّله، ويخرج.

### ويندوز — Task Scheduler

```powershell
schtasks /create /tn "CS Edge Jobs" /sc minute /mo 5 ^
  /tr "cmd /c cd /d C:\Users\nasse\Desktop\market-scanner\market-scanner && python web\manage.py run_jobs >> data\jobs.log 2>&1"
```

`/mo 5` كل خمس دقائق. اجعله أقصر من أقصر فترة عندك.

### لينكس — cron

```
*/5 * * * * cd /path/to/market-scanner && python web/manage.py run_jobs >> data/jobs.log 2>&1
```

## ولا يعملان معاً

المحرّك الداخلي والأمر الخارجي يقرآن `next_run` نفسه، فلا يريان
المهمّة مستحقّة معاً في الغالب. لكن **لا قفل بين عمليتين**: قد
يلتقيان على مهمّة في اللحظة نفسها فتُشغَّل مرّتين.

فإن ربطت الأمر الخارجي، أوقف المحرّك الداخلي:

```
SCHEDULER_ENGINE=off
```

## الحالات

| الحالة | المعنى |
|---|---|
| **نجحت** | عملت وانتهت |
| **فشلت** | خطأ حقيقي — اقرأ الرسالة |
| **مؤجَّلة** | المورد كان مشغولاً بدورة سابقة. ليست فشلاً: تُعاد بعد ٩٠ث |
| **تعمل الآن** | دورة جارية |

### ولماذا تتزاحم مهامّ المسح

`scheduler` يملك **قفلاً واحداً لكل الأسواق** — فلا يُمسح سوقان
معاً. وثلاث مهامّ مسحٍ تستحقّ في اللحظة نفسها تعني أنّ واحدة تعمل
واثنتين تُؤجَّلان.

ولذلك يوزّعها البذر على دقائق متتالية. ومن بذر قبل هذا الإصلاح:

```
python web/manage.py run_jobs --stagger
```

## المفاتيح

| المفتاح | القيمة | الأثر |
|---|---|---|
| `SCHEDULER_ENGINE` | `cron` (افتراضي) | محرّك واحد يقرأ القاعدة |
| | `off` | لا جدولة داخل الخادم |
| | `legacy` | الخيوط الأربعة القديمة — مخرج طوارئ |

متغيّرات الفترات القديمة (`WATCH_INTERVAL_SECONDS` وأخواتها)
تُقرأ **عند البذر الأوّل فقط**. بعده الفترة في القاعدة، وتُغيَّر
من الواجهة.

## الأوامر

```
python web/manage.py run_jobs            # شغّل المستحقّ
python web/manage.py run_jobs --list     # اعرض الحالة بلا تشغيل
python web/manage.py run_jobs --force scan:crypto
python web/manage.py run_jobs --seed     # أنشئ الناقصة
```
