# نقل بياناتك إلى الخادم

بياناتك على جهازك، والخادم فارغ. هذا الدليل ينقلها كاملةً
ويُثبت أنّها وصلت.

| | |
|---|---:|
| صفوف القاعدة | **24,679** في ١٣ جدولاً |
| شموع الأسواق الثلاثة | **224 م.ب** |
| لقطات الميزات وذاكرة المحلّل | **818 م.ب** |
| المجموع على القرص | **1.12 غ.ب** في ٤٬٢٠٣ ملفّات |
| **بعد الضغط — ما يُنقل فعلاً** | **150 م.ب** (١٣٪) |

الأرقام مقيسة لا مقدَّرة: التحزيم الفعليّ استغرق ٨٩ ثانية
واستبعد ٢٢١ ملفّاً (٢١٦ قفلاً وخمسة ملفّات SQLite).

والمهمّ فيها ليس الحجم: **٧٢١ صفقة محسومة** هي أساس كل نسبةٍ
قِيست في هذا المشروع. تُفقَد فتُفقَد معها كل إجابةٍ عن «هل هذا
يعمل؟».

---

## قبل أن تبدأ

**رحّل قاعدتك المحلّية إلى PostgreSQL أوّلاً.** الحزمة تُبنى من
Postgres لا من SQLite. إن لم تفعل بعد، اتبع
[POSTGRES.md](POSTGRES.md) خطواتٍ ١ إلى ٤، ثمّ عُد.

**وحدّث الخادم من GitHub.** استعادة بياناتٍ في صورةٍ أقدم من
هجراتها تُنتج أعمدةً مفقودة:

```bash
cd ~/market-scanner && git pull
```
أو من بورتينر: ‎Stacks ← market-scanner ← Pull and redeploy‎.

---

## ١) أوقف كل ما يكتب — محلّياً

**ليست خطوةً اختيارية.** التحزيم أثناء الكتابة يترك صفوفاً خارج
النسخة بلا إنذار.

أغلق خادم Django، وتأكّد أنّ `SCHEDULER_ENGINE=off` في `.env`.

---

## ٢) ابنِ الحزمة

```powershell
python tools_ship.py --check     # مقارنةٌ بلا كتابة
python tools_ship.py             # البناء
```

`--check` يقارن SQLite بـPostgres جدولاً جدولاً. وهو ما يمنع
العطب الصامت الأشيع: من رحّل ثمّ عاد فعمل على SQLite أسبوعاً
يحزم `pg_dump` عنده الماضي. **و‏Postgres أكثرُ سليم** — بعد
الترحيل تكتب وحدها. **وأقلُّ رفض.**

ينتج في `ship\`:

```
scanner.dump        نسخة القاعدة (‎-Fc‎: تحمل التسلسلات وترتيب الاستعادة)
appdata.tar.gz      محتوى data/
reports.tar.gz      محتوى reports/
SHA256SUMS          بصمة كل ملفّ
EXPECTED_ROWS       العدد المتوقَّع لكل جدول
docker-restore.sh   سكربت الاستعادة
manifest.json       ماذا ومتى ومن أيّ commit
```

**وما يُستبعَد عمداً:**

| | لماذا |
|---|---|
| `*.lock` (٢١٦ ملفّاً) | قفلٌ منسوخ يجعل `market_sync` يظنّ الرمز قيد المزامنة فيتخطّاه — بلا خطأ، وبلا شمعةٍ جديدة، أبداً |
| `dashboard.sqlite3*` | القاعدة صارت Postgres. ونسخُه إلى الخادم يُغري بتشخيص أيّ خللٍ لاحق من القاعدة الخطأ |
| `.django_secret_key` | للخادم مفتاحه، وتبديله يُبطل الجلسات بلا مقابل |

## ٣) انقل

```powershell
scp -r ship user@server:~/scanner-ship
```

١٥٠ ميغابايت. على ١٠ م.ب/ث ≈ دقيقتان ونصف.

---

## ٤) استعِد

```bash
ssh user@server
bash ~/scanner-ship/docker-restore.sh ~/scanner-ship
```

وإن كان اسم مكدّسك في بورتينر غير `market-scanner`:

```bash
STACK=<الاسم> bash ~/scanner-ship/docker-restore.sh ~/scanner-ship
```

(السكربت يطبع الأسماء المتاحة إن لم يجد المكدّس.)

### ما يفعله، بالترتيب

| | | ولماذا هنا بالذات |
|---|---|---|
| ١ | يتحقّق من البصمات | ١٥٠ م.ب عبر الشبكة تُقطع. والتحقّق **قبل** أن يمسّ شيئاً |
| ٢ | يجد الحاويات والوحدات | باسم الخدمة في لافتات compose، والوحدة من `docker inspect` — لا تخميناً لبادئة المشروع |
| ٣ | يوقف `web` و`scheduler` | الاستعادة على قاعدةٍ يكتب فيها المجدول تترك جداول نصفَ مستعادة |
| ٤ | ينسخ ما على الخادم الآن | مسار التراجع الوحيد، ولحظة أخذه هي هذه |
| ٥ | يفرّغ ويستعيد | `DROP SCHEMA` ثمّ `pg_restore` — أرضٌ معروفة |
| ٦ | يفكّ الأرشيفين في الوحدتين | فوق الموجود، بلا حذف |
| ٧ | **يعدّ كل جدول ويقارنه** | البرهان. ولا يقول «تمّ» إن اختلف واحد |
| ٨ | يعيد التشغيل | |

## ٥) وتأكّد بنفسك

افتح اللوحة، ثمّ:

- **الصفقات** — ٧٢١ محسومة
- **سجلّ الرصد** — ١٬٢٩٧ صفّاً
- **`/jobs/`** — راقب دورتين. أوّل `market_sync` يجب أن يكون
  قصيراً: الشموع موجودة، فلا شيء يُنزَّل

---

## الأعطال المتوقّعة

**`بصمةٌ لا تطابق`** — النقل قُطع. أعد `scp` وحسب؛ لم يُمَسّ شيء
على الخادم.

**`لا حاوية db في مكدّس …`** — اسم المكدّس مختلف. السكربت يطبع
الأسماء المتاحة تحت الرسالة؛ أعد بـ`STACK=<الاسم>`.

**`لا جداول في Postgres المحلّية`** — لم ترحّل بعد.
[POSTGRES.md](POSTGRES.md) خطوات ١–٤.

**`Postgres المحلّية ناقصة`** — رحّلت ثمّ عملت على SQLite بعدها.
أعد `migrate_to_postgres` قبل التحزيم.

**جدولٌ لا يطابق بعد الاستعادة** — السكربت يخرج بـ1 ويطبع مسار
نسخة التراجع. لا تعتمد على البيانات حتى يُفهَم السبب. وأشيعه:
صورةٌ على الخادم أقدم من الهجرات — `git pull` ثمّ أعد النشر
والاستعادة.

**الشموع موجودة والمسح لا يراها** — تحقّق أنّ الجذر صحيح:

```bash
docker exec <web> ls /app/data/crypto/15m | head
```

يجب أن ترى `.npz` مباشرةً. ولو رأيت `/app/data/data/…` فالأرشيف
بُني بجذرٍ خاطئ — أعد بناءه.

## التراجع

نسخة ما قبل الاستعادة في مجلّد الحزمة على الخادم:

```bash
docker cp ~/scanner-ship/pre-restore-*.dump <db>:/tmp/back.dump
docker exec <db> psql -U scanner -d scanner \
    -c 'DROP SCHEMA public CASCADE; CREATE SCHEMA public;'
docker exec <db> pg_restore -U scanner -d scanner --no-owner /tmp/back.dump
```

**وجهازك لا يُمَسّ في هذا كلّه.** لا `tools_ship.py` ولا السكربت
يكتب حرفاً في `data/` المحلّي. احتفظ بـ`dashboard.sqlite3`
**شهراً على الأقلّ**.

---

## وتكراره لاحقاً

الأداة والسكربت يعملان مرّةً بعد مرّة. عند كل نقلٍ تالٍ يُستبدَل
ما على الخادم بما عندك — فانقل في اتّجاهٍ واحد، ولا تدع الخادم
يجمع صفقاتٍ تريد الاحتفاظ بها بينما تنقل فوقها.

والأنظف حين يستقرّ الخادم: اجعله هو العامل، وأوقف المجدول
محلّياً.
